# Module 8: Kerberos and NTLM

**Priority: P0 — Authentication protocols. Understanding these = understanding AD attacks.**

---

## 8.1 Kerberos — The Protocol

### Core Concept
**Ticket-based authentication** using symmetric cryptography and a trusted third party (KDC). No passwords on the wire.

### Key Components
| Component | Role |
|-----------|------|
| **Client** | User/service requesting access |
| **KDC (Key Distribution Center)** | Runs on every DC. Two services: AS (Authentication Service) + TGS (Ticket Granting Service) |
| **AS (Authentication Service)** | Issues TGT (Ticket Granting Ticket) |
| **TGS (Ticket Granting Service)** | Issues Service Tickets (ST) |
| **Service/Resource** | Target (file share, web app, SQL, etc.) |
| **SPN (Service Principal Name)** | Identity of service (HTTP/web01.domain.com, MSSQLSVC/sql01.domain.com:1433) |

### Kerberos Keys (Derived from Password)
| Key | Usage |
|-----|-------|
| **User Long-term Key** | Derived from user password (AES256, AES128, RC4_HMAC_MD5) |
| **Service Long-term Key** | Derived from service account password |
| **Session Key** | Generated by KDC, encrypted for client + service |
| **TGT Session Key** | Client ↔ KDC (TGS) |
| **Service Session Key** | Client ↔ Service |

## 8.2 Kerberos Flow — Step by Step

### Phase 1: AS-REQ / AS-REP (Get TGT)
```
Client                                    KDC (AS)
   │                                          │
   ├─ AS-REQ ────────────────────────────────►│
   │  • cname (user@DOMAIN.COM)               │
   │  • sname (krbtgt/DOMAIN.COM)             │
   │  • Timestamp (encrypted with user key)   │
   │  • PaData: PA-ENC-TIMESTAMP (pre-auth)   │
   │                                          │
   │                                          ├─ Verify pre-auth (decrypt timestamp)
   │                                          ├─ Check account (enabled, not expired, etc.)
   │                                          ├─ Generate TGT Session Key
   │                                          ├─ Build TGT:
   │                                          │   • cname, crealm
   │                                          │   • Ticket flags (forwardable, renewable, etc.)
   │                                          │   • Auth time, start time, end time, renew-till
   │                                          │   • TGT Session Key
   │                                          │   • Encrypted with **krbtgt key** (only KDC can read)
   │                                          │
   │                                          ├─ Build AS-REP:
   │                                          │   • TGT Session Key (encrypted with **user key**)
   │                                          │   • TGT (opaque to client)
   │                                          │
   │◄─ AS-REP ────────────────────────────────┤
   │                                          │
```

**Pre-Authentication (PA-ENC-TIMESTAMP)**: Client encrypts timestamp with user key. Proves identity without sending password. **Disabled = AS-REP Roasting vulnerable.**

### Phase 2: TGS-REQ / TGS-REP (Get Service Ticket)
```
Client                                    KDC (TGS)
   │                                          │
   ├─ TGS-REQ ────────────────────────────────►│
   │  • TGT (from AS-REP)                     │
   │  • Authenticator (encrypted with TGT Session Key):
   │     • cname, ctime, cusec, subkey (optional)
   │  • sname (SPN: HTTP/web01.domain.com)    │
   │  • Ticket flags (forwardable, etc.)      │
   │                                          │
   │                                          ├─ Decrypt TGT (krbtgt key) → get TGT Session Key
   │                                          ├─ Decrypt Authenticator (TGT Session Key)
   │                                          ├─ Verify: cname matches, time skew < 5 min, replay cache
   │                                          ├─ Check SPN exists, service account valid
   │                                          ├─ Check delegation / constrained delegation
   │                                          ├─ Generate Service Session Key
   │                                          ├─ Build Service Ticket (ST):
   │                                          │   • cname, crealm
   │                                          │   • Service Session Key
   │                                          │   • Flags, times
   │                                          │   • **Encrypted with SERVICE ACCOUNT KEY**
   │                                          │
   │                                          ├─ Build TGS-REP:
   │                                          │   • Service Session Key (encrypted with TGT Session Key)
   │                                          │   • Service Ticket (opaque to client)
   │                                          │
   │◄─ TGS-REP ────────────────────────────────┤
   │                                          │
```

### Phase 3: AP-REQ / AP-REP (Access Service)
```
Client                                    Service
   │                                          │
   ├─ AP-REQ ────────────────────────────────►│
   │  • Service Ticket (ST)                   │
   │  • Authenticator (encrypted with Service Session Key):
   │     • cname, ctime, cusec, subkey, seq#
   │  • Optional: Mutual auth requested       │
   │                                          │
   │                                          ├─ Decrypt ST (service account key) → Service Session Key
   │                                          ├─ Decrypt Authenticator (Service Session Key)
   │                                          ├─ Verify: cname, time, replay
   │                                          ├─ **Authorization**: Check token (SIDs from PAC) vs DACL
   │                                          │
   │                                          │  (If mutual auth requested)
   │                                          ├─ Build AP-REP:
   │                                          │   • Server time (encrypted with Service Session Key)
   │                                          │
   │◄─ AP-REP (optional) ─────────────────────┤
   │                                          │
```

## 8.3 Critical Kerberos Structures

### PAC (Privilege Attribute Certificate) — **Inside TGT & Service Ticket**
```
PAC Contains:
├── Logon Info: User SID, Group SIDs, Primary Group, Logon Time, Logoff Time, Kickoff Time, Password Last Set, Password Can Change, Password Must Change, Effective Name, Full Name, Logon Script, Profile Path, Home Directory, Home Dir Drive, Logon Server, Logon Domain Name, Domain SID
├── Credentials Info: (supplemental creds for NTLM, etc.)
├── Server Checksum: KDC signature (krbtgt key)
├── KDC Checksum: Service account key signature
└── **UPN/DNS Info** (optional)
```

**Why PAC matters**: 
- **Authorization data** — Groups/SIDs determine access
- **Silver Ticket** — Forge Service Ticket with custom PAC
- **Golden Ticket** — Forge TGT with custom PAC (needs krbtgt hash)

### Ticket Flags (Bitmask)
| Flag | Hex | Meaning |
|------|-----|---------|
| **Forwardable** | 0x40000000 | Can be forwarded (delegation) |
| **Forwarded** | 0x00000001 | Already forwarded |
| **Proxiable** | 0x20000000 | Can be proxied (constrained delegation) |
| **Proxy** | 0x00000002 | Is a proxy ticket |
| **Renewable** | 0x00000008 | Can be renewed (up to renew-till) |
| **Initial** | 0x00000010 | TGT (not service ticket) |
| **Pre-Authent** | 0x00000020 | Pre-auth used |
| **HW-Authent** | 0x00000040 | Hardware auth (smartcard) |
| **Ok-As-Delegate** | 0x00000080 | Service trusted for delegation |

## 8.4 Kerberos Encryption Types (etype)

| etype | Algorithm | Status |
|-------|-----------|--------|
| **18** | AES256-CTS-HMAC-SHA1-96 | **Preferred** |
| **17** | AES128-CTS-HMAC-SHA1-96 | Good |
| **23** | RC4-HMAC-MD5 | **Weak** (Kerberoasting target) |
| **3** | DES-CBC-MD5 | **Disabled** (legacy) |
| **1/2** | DES-CBC-CRC | **Disabled** |

**Check**: `msDS-SupportedEncryptionTypes` on user/computer. **28 (16+8+4) = AES256 + AES128 + RC4**. **24 (16+8) = AES only (secure)**.

## 8.5 Kerberos Attacks — Detection Focus

### 1. Kerberoasting (TGS-REQ for Service Accounts)
**Attack**: Request TGS for SPN → Get ST encrypted with service account key → Offline crack (RC4 = easy).
**Prereqs**: Any domain user, SPN exists on service account.
**Event**: **4769** (TGS-REQ) with `TicketEncryptionType = 0x17 (RC4)` targeting service accounts.
```kql
SecurityEvent
| where EventID == 4769
| where TicketEncryptionType == 23  // RC4
| where TargetUserName has "@"  // SPN format
| summarize Count=count(), Services=make_set(ServiceName) by TargetUserName, IpAddress, TimeGenerated bin 1h
| where Count > 10
```

### 2. AS-REP Roasting (No Pre-Auth)
**Attack**: Request AS-REQ for user WITHOUT pre-auth → Get AS-REP with encrypted TGT Session Key → Offline crack.
**Prereqs**: User has `DONT_REQUIRE_PREAUTH` (UF_DONT_REQUIRE_PREAUTH = 0x400000 in userAccountControl).
**Event**: **4768** (AS-REQ) with `PreAuthType = 0` (no pre-auth) + **4771** (Pre-Auth Failed) for same user.
```kql
SecurityEvent
| where EventID == 4768
| where PreAuthType == 0  // No pre-auth
| join kind=inner (
    SecurityEvent
    | where EventID == 4771
    | project TargetUserName, TimeGenerated, FailureCode
) on TargetUserName
```

### 3. Pass-the-Ticket (PtT)
**Attack**: Steal TGT/ST from memory (LSASS) → Inject into session → Access as user.
**Tools**: Rubeus, Mimikatz (`kerberos::ptt`)
**Detection**: 
- **4624 Logon Type 9** (NewCredentials) with unusual source
- **4672** (Special Logon) without preceding 4624
- Multiple TGTs for same user from different IPs
- Ticket lifetime anomalies (10hr default, 7d renewable)

### 4. Golden Ticket
**Attack**: Forge TGT using **krbtgt hash** → Any user, any group, any lifetime (10yr default).
**Prereqs**: Domain Admin (or equivalent) to dump krbtgt hash (DCSync, NTDS.dit).
**Detection**:
- TGT with **non-standard PAC** (groups not matching AD)
- TGT lifetime > 10 hours (default) or weird renew-till
- **4768** from unusual source (not user workstation)
- krbtgt password age > 180 days (rotation indicator)

### 5. Silver Ticket
**Attack**: Forge **Service Ticket** using **service account hash** → Access specific service.
**Prereqs**: Service account hash (Kerberoasting, DCSync, local admin on server).
**Detection**:
- **4769** for service not matching user's normal access
- Service Ticket with custom PAC (e.g., Domain Admin SIDs for HTTP service)
- No corresponding TGS-REQ (4769) from KDC (forged locally)

### 6. Skeleton Key
**Attack**: Patch LSASS on DC → Universal "master password" for any user.
**Detection**: 
- **4624** success for accounts with wrong password (no 4625 preceding)
- DC LSASS memory patch (EDR)
- Unusual auth patterns across many accounts

### 7. Delegation Attacks
| Type | Mechanism | Abuse |
|------|-----------|-------|
| **Unconstrained** | `TRUSTED_FOR_DELEGATION` | Compromise server → steal TGTs of connecting users |
| **Constrained** | `msDS-AllowedToDelegateTo` (SPN list) | Compromise server → request ST for listed SPNs |
| **Resource-Based (RBCD)** | `msDS-AllowedToActOnBehalfOfOtherIdentity` on resource | Write access on resource → add attacker → impersonate any user |

**Detection**: 
- 5136: `msDS-AllowedToActOnBehalfOfOtherIdentity` modification (RBCD)
- 4769: S4U2Self + S4U2Proxy (constrained delegation flow)
- Computer accounts with `TRUSTED_FOR_DELEGATION` (unconstrained)

## 8.6 NTLM — The Legacy Protocol

### Why It Still Exists
- Pre-Windows 2000 compatibility
- Workgroup / non-domain auth
- Local accounts
- Fallback when Kerberos fails (SPN missing, DNS issues, firewall)
- Some apps hardcode NTLM

### NTLM Versions
| Version | Challenge/Response | Security |
|---------|-------------------|----------|
| **NTLMv1** | DES-based, 56-bit | **Broken** (2012) |
| **NTLMv2** | HMAC-MD5, variable challenge | **Better** but relayable |
| **NTLMv2 Session Security** | Signing/Sealing | Adds integrity |

### NTLM Authentication Flow
```
Client                                    Server/DC
   │                                          │
   ├─ NEGOTIATE_MESSAGE ─────────────────────►│
   │  • Flags (signing, sealing, target info) │
   │                                          │
   │◄─ CHALLENGE_MESSAGE ────────────────────┤
   │  • Server Challenge (8 bytes)            │
   │  • Target Info (AV_PAIRS: DNS, SPN, etc) │
   │                                          │
   ├─ AUTHENTICATE_MESSAGE ─────────────────►│
   │  • Username, Domain                      │
   │  • LM Response (NTLMv1) / NTLMv2 Response│
   │  • NT Response (NTLMv2)                  │
   │  • Session Key (derived)                 │
   │                                          │
   │          (Server validates against DC    │
   │           via Netlogon Secure Channel)   │
   │                                          │
   │◄─ Result ────────────────────────────────┤
   │                                          │
```

### NTLM Hashes
| Hash | Algorithm | Use |
|------|-----------|-----|
| **LM Hash** | DES(uppercase password) | **Disabled by default** (NoLMHash policy) |
| **NT Hash (NTLM)** | MD4(UTF-16LE(password)) | **What's stored in NTDS.dit / SAM** |
| **NTLMv1 Response** | DES(NT Hash, Challenge) | Broken |
| **NTLMv2 Response** | HMAC-MD5(NT Hash, Challenge + Client Nonce + Target Info) | Current |

**Key Fact**: **NT Hash = Password Equivalent**. Pass-the-Hash uses NT Hash directly.

## 8.7 NTLM Attacks

### 1. Pass-the-Hash (PtH)
**Attack**: Use NT Hash (no password needed) → Authenticate as user.
**Tools**: Mimikatz (`sekurlsa::pth`), Rubeus (`pth`), Impacket (`psexec.py -hashes`)
**Requirement**: NTLM auth (not Kerberos). Works for: SMB, WinRM, RPC, LDAP, MSSQL.
**Detection**:
- **4624 Logon Type 3** (Network) + **4776** (NTLM on DC) for same user from different sources
- No preceding 4625 (failed logon)
- Source: unusual (workstation not user's)
- **EDR**: LSASS access + NTLM auth from same process

### 2. NTLM Relay
**Attack**: Intercept NTLM auth → Relay to another service → Authenticate as victim.
**Tools**: ntlmrelayx.py, PetitPotam (coerce auth), ntlmrelayx + AD CS (ESC8)
**Prereqs**: 
- No signing required (SMB signing disabled, LDAP signing disabled)
- Target service accepts NTLM
**Detection**:
- **4624/4776** from relay machine (not user workstation)
- Multiple auths from same source IP for different users
- **Event 5156** (Filtering Platform) showing connection to relay target
- **PetitPotam**: 4624 Type 3 from DC$ (computer account) to CA/WebDAV

### 3. Password Spray (NTLM)
**Attack**: One password (e.g., "Password123") → Many users → Avoid lockout.
**Protocol**: Often NTLM (Kerberos pre-auth also works).
**Detection**:
- **4625** / **4776** with `Status = 0xC000006A` (bad password) across many users
- Same source IP, low volume per user (1-3), high total
- Often targets service accounts (no lockout policy)

### 4. Relay to AD CS (ESC8 / PetitPotam)
**Attack**: Coerce DC to auth to attacker (MS-EFSRPC) → Relay to AD CS HTTP endpoint → Enroll cert for DC$ → Request TGT (PKINIT) → Domain Admin.
**Detection**: 
- 4624 Type 3 from DC$ to CA server (port 80/443)
- Cert enrollment for DC$ (CA logs)
- Subsequent 4768 (PKINIT) for DC$

## 8.8 Kerberos vs NTLM — Comparison

| Aspect | Kerberos | NTLM |
|--------|----------|------|
| **Mechanism** | Tickets (TGT + ST) | Challenge/Response |
| **Crypto** | Symmetric (AES/RC4) | Hash-based (MD4/MD5) |
| **Mutual Auth** | Yes (AP-REP) | Optional (NTLMv2) |
| **Delegation** | Yes (constrained/unconstrained) | No |
| **Offline Crack** | Kerberoasting (ST), AS-REP Roasting | NTLMv2 hash capture |
| **Relay** | No (tickets bound to service) | **Yes** (major risk) |
| **Pass-the-Hash** | No (need krbtgt for Golden) | **Yes** (NT Hash) |
| **Credential Storage** | Keys derived from password | NT Hash in memory/NTDS.dit |
| **Default in Domain** | Yes (preferred) | Fallback only |

## 8.9 Critical Event IDs Summary

| Event ID | Protocol | Phase | Key Fields |
|----------|----------|-------|------------|
| **4768** | Kerberos | AS-REQ/REP | TargetUserName, ServiceName (krbtgt), PreAuthType, TicketEncryptionType, ResultCode, IpAddress |
| **4769** | Kerberos | TGS-REQ/REP | TargetUserName, ServiceName (SPN), TicketOptions, TicketEncryptionType, ResultCode, IpAddress |
| **4770** | Kerberos | TGS Renewal | Similar to 4769 |
| **4771** | Kerberos | Pre-Auth Failed | TargetUserName, ServiceName, FailureCode (0x18=bad pwd), PreAuthType |
| **4772** | Kerberos | TGT Request Failed | Similar to 4768 failure |
| **4776** | NTLM | DC Validation | TargetUserName, Workstation, Status (0x0=success), IpAddress (if logged) |
| **4624** | Both | Logon | LogonType, AuthenticationPackage (Kerberos/NTLM), LogonProcessName, IpAddress |
| **4625** | Both | Failed Logon | Status, SubStatus, LogonType, AuthenticationPackage |

## 8.10 Detection Queries (KQL)

### Kerberoasting
```kql
SecurityEvent
| where EventID == 4769
| where TicketEncryptionType == 23  // RC4
| where ServiceName has "@"  // SPN format
| summarize Count=count(), Services=make_set(ServiceName), Start=min(TimeGenerated), End=max(TimeGenerated) 
  by TargetUserName, IpAddress, Computer, bin(TimeGenerated, 1h)
| where Count >= 10
| extend Duration = End - Start
```

### AS-REP Roasting
```kql
SecurityEvent
| where EventID == 4768
| where PreAuthType == 0  // No pre-auth
| join kind=inner (
    SecurityEvent
    | where EventID == 4771
    | project TargetUserName, TimeGenerated, FailureCode
) on TargetUserName
| where FailureCode == 0x18  // Bad password (attacker trying)
```

### Pass-the-Hash
```kql
// NTLM success without prior failure
SecurityEvent
| where EventID == 4624 and LogonType == 3 and AuthenticationPackage == "NTLM"
| join kind=leftanti (
    SecurityEvent
    | where EventID == 4625 and LogonType == 3
    | project TargetUserName, IpAddress, TimeGenerated
) on TargetUserName, IpAddress
| where TimeGenerated > ago(1h)
```

### NTLM Relay (PetitPotam)
```kql
SecurityEvent
| where EventID == 4624 and LogonType == 3
| where TargetUserName endswith "$"  // Computer account
| where TargetUserName == "DC01$"  // Specific DC
| where IpAddress == "10.10.10.50"  // CA / WebDAV server
```

### Golden Ticket Indicators
```kql
SecurityEvent
| where EventID == 4768
| where TicketOptions has "renewable"  // Check renew-till
| extend RenewTill = parse_timestamp(...)
// Look for: renew-till > 10 years, unusual groups in PAC (hard from logs alone)
// Better: EDR detection of forged tickets, krbtgt password age
```

## 8.11 Interview Questions for This Module

1. **Explain the Kerberos AS-REQ/AS-REP flow and what pre-authentication does.**
   - Client requests TGT from AS, encrypts timestamp with user key (pre-auth). KDC verifies, returns TGT (encrypted with krbtgt key) + TGT Session Key (encrypted with user key).

2. **What is the difference between a TGT and a Service Ticket?**
   - TGT: From AS, encrypted with krbtgt key, used to request Service Tickets from TGS. Service Ticket: From TGS, encrypted with service account key, used to access specific service (AP-REQ).

3. **What is Kerberoasting and what Event ID detects it?**
   - Request TGS for SPN (service account) → Get ST encrypted with service key → Offline crack. **Event 4769** with RC4 (etype 23) encryption.

4. **What is AS-REP Roasting and what user attribute enables it?**
   - Request AS-REQ without pre-auth → Get encrypted TGT Session Key → Offline crack. Enabled by `userAccountControl` flag `DONT_REQUIRE_PREAUTH` (0x400000).

5. **Explain Pass-the-Hash vs Pass-the-Ticket.**
   - PtH: Use NT Hash for NTLM auth (SMB, WinRM, etc.). PtT: Inject stolen Kerberos ticket (TGT/ST) into session for Kerberos auth.

6. **What is a Golden Ticket and what hash is needed to forge it?**
   - Forged TGT with custom PAC (any user, any groups, long lifetime). Needs **krbtgt hash** (Domain Admin / DCSync).

7. **What is a Silver Ticket and how does it differ from Golden?**
   - Forged Service Ticket (not TGT) using **service account hash**. Only accesses that specific service. No KDC interaction.

8. **How does NTLM Relay work and what prevents it?**
   - Intercept NTLM auth → Relay to target service. Prevented by: **SMB signing**, **LDAP signing**, **EPA (Extended Protection for Auth)**, **Disable NTLM**.

9. **What Event ID shows NTLM authentication on a Domain Controller?**
   - **4776** (Credential Validation). Shows TargetUserName, Workstation, Status.

10. **What is Resource-Based Constrained Delegation (RBCD) and what attribute controls it?**
    - Delegation where *resource* controls who can delegate to it. Attribute: `msDS-AllowedToActOnBehalfOfOtherIdentity` on the resource computer/user object.
